# 汇典楼正门中轴：限定只读核查（2026-11-07）

## 建议范围

优先处理北馆正门两组台阶之间的中轴前场，而不是泛化重建图书馆。项目现存的 `build/campus-research-reference/library-north.webp` 可见正面入口、两组台阶、其间的铺装以及两侧较低的石砌边界/绿化；图片分辨率不足以确认砖的材质、纹路、大小和施工细部。`data/SOURCES.md` 的汇典楼条目记录照片与 OSM 线位用途，并明确几何和标高都未经实测。

## 高程与行走面

- `generate_campus.py` 把两段台阶直接写入 `campus-bridge.mesh`；`main.cpp` 的 `WalkSurfaces` 已加载同一网格，并只读取朝上法线不低于 0.7 的三角面。故不能说两段正门台阶没有行走网格；能否连续到达仍需要结合最终生成网格和地形逐点验证。
- 外侧台阶代码按两端高程判断是否反转线序，底部高程为端点 `surface_height` 加不少于 0.12 m 的 `lift`，`lift` 又由沿线中心和两侧采样确定；首块踏面还有一级增量。不能仅根据共用 OSM 节点断定它与路面严丝合缝。所用 `surface_height` 为粗网格双线性插值，而相机和车道使用三角面插值；普通车道铺装若在其生成范围内，视觉面为地形 +0.035 m，贴地相机以地形和 `WalkSurfaces` 为准。
- 靠楼台阶最后一级设为生成器 `surface_height(-126.4,-102.9)+0.12`。北馆地面薄板上表面为运行时 `TerrainHeights.at(-126.4,-102.9)+0.24`；后者与前者插值不同，故两者的名义差不是必然恰好 0.12 m，需用当前地形数据核验。上层平台顶面是运行时楼基准 +4.35 m；两侧连廊按生成器基准 +4.35 m，二者同样存在插值差待验证。`bridge-profile.json` 记载连廊 34.71 m 是历史生成估算，不能单独证明当前运行高程。
- `WalkSurfaces.at` 选最高可到达表面，向上限制为前一脚下高程 +0.8 m，且表面不得低于地形 0.05 m 以上。两段台阶均有网格不等于坡面、两端及两侧没有埋入或跳层。北馆一层薄板、二层外挑平台和两侧楼梯由 `northLibrary` 的盒体渲染，并未单独作为对应行走网格加载；二层侧梯属于另一个连接问题，本次不建议顺带重建。

## 后续最小实现建议（本次未实施）

1. 仅在中轴两段之间做约 6.6 m 宽的铺装衔接，以 x≈1.6、z≈41.01–56.97 为初始范围，裁入 OSM 人行面，保留既有两组台阶和路口，不占用 232096328 车行道。先核查是否已有独立铺装，避免重复生成或叠面。灰色砖式纹理可作为设计近似，不得标注为照片证明的真实铺装。
2. 用当前实际三角地形高度和现存踏面高度分别检查车道—外侧台阶—前场—靠楼台阶—一层薄板的接缝与左右边缘；依实际差值选择局部过渡或调整端点，避免简单放置固定高度的整块平台。若铺装高于地面，应明确是否需要将其可行走踏面纳入 `WalkSurfaces`，同时避免覆盖高架或重复可走面。
3. 复用当前 `verifyEntryWalk` 的地形/`WalkSurfaces.at` 逻辑做双向密集采样：核对预计踏面高程、上升与下降、道路及楼前端点，并对两侧边缘采样；原检查器阈值为脚高误差 0.05 m、相邻点高差 0.31 m。按禁止 GUI 的约束只做命令行或离线数值验证，未验证的画面效果保持不确定。

本次只读了指定源文件、OSM 快照、资料和参考图，没有读取运行资源、启动程序、生成网格或修改主程序。高差、砖纹、现状与成图效果仍待核实。
