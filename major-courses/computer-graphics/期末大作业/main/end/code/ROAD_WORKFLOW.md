# 校园道路与绿化：可重复的建模流程

本流程先在隔离副本上工作，适用于逐段提高粤海校区的道路和景观还原度。立德门右侧步道是第一个样板：地面照片支持红色铺装和浅色边缘；中心线、宽度、门岗轮廓和树木位置不属于实测。照片只用于观察，不打包为纹理。

## 1. 保存基线并定位

先保存现有 `code`、`assets`、配置和一组固定视角截图。原项目生成器会重写大量网格和数据，应在隔离副本里运行，尤其要保留其他工作中尚未完成的文件。记录真实资料的地址、日期、拍摄方向、可确认的结构和未知项；OSM 有缺漏，影像也可能过时。校对坐标时使用项目已有的 OSM 地图、地图编号及投影转换，避免用照片目测捏造坐标。

## 2. 建立可替换的语义数据

`data/lide-walk.json` 分开记录参考、估计中心线、宽度、边带宽度与门岗避让轮廓。只有能从资料判断的内容才作为事实；坐标、尺度和照片无法确定的区域明确记为估计。后续路段应建立各自独立的记录，包含资料、坐标系、范围、道路侧别、路径、铺装、树池、绿化边界以及置信度；没有足够证据就保留现有近似，不要将本段样式推广到全校。

## 3. 生成和避让

`generate_campus.py` 中 `make_lide_walk` 使用配置生成独立的砖面与边带，按已有车道、建筑和门岗轮廓裁切，并使用渲染地形的三角网贴地。旧底图中的红色步道已移除，防止底图和新网格重复。道路、人行道、路缘和绿植应分别作为图层；路口、坡道、树池或复杂出入口先按实际形态单独建模，不把它们套成统一道路缓冲。

依赖：Python 3.12、Pillow、numpy、Shapely 2、mapbox-earcut，以及项目所需的 C++/CMake、GLFW、GLAD 和 GLM。下列命令在 **隔离副本** `code` 目录中运行；确保 Python 已能导入所需包：

```powershell
python generate_campus.py
python verify_lide_walk.py
```

完整生成会写入所有 `assets` 及部分 `data`，应先检查生成前后的文件差异，再决定哪些产物可以合并。项目的 `verify_scene_data.py` 会被样板验证脚本调用，额外检查全场景的道路、桥与资源一致性。样板检查网格完整性、铺装连通性、车道和门岗避让以及与渲染地形的高度差。几何测试不能代替照片或现场核对。

## 4. 编译和固定视角对比

按根目录 `AGENTS.md` 使用统一 CMake 构建；提交包内的 `code/CMakeLists.txt` 也可用于隔离副本的独立构建。运行程序的 `--self-test`，再用相同相机、分辨率、场景资源和光照生成前后截图。例如，从可执行程序及其 `assets` 所在目录运行：

```powershell
.\szu-campus.exe --self-test
.\szu-campus.exe --gate=lide --capture=C:/temp/lide.ppm
```

依次检查轮廓与道路关系、连续步行空间、路缘和树池、贴图尺度、植被遮挡与性能；近景、俯视和步行高度至少各留一张。需要步行交互时还要在窗口中实际走过入口，避免只凭截图判断可达。照片与模型的时间、季节和拍摄方向可能不同。

## 5. 应用与下一段

核对目标项目在备份后未被其他线程改动，再只同步已审查的源码、语义数据与对应资源，重新构建并确认可执行文件读取的是新资源。保留变更前文件和同视角截图。先对第二处有可靠资料的路段试用，再考虑把重复的数据结构抽成通用配置格式；灌木和行道树优先参考可辨识的真实位置，其余只在已确认绿化区域受约束生成，并标明估计。

## 6. 标注树点和绿化带

`data/planting-annotations.json` 保留立德门原灌木区域的来源，离散株数已设为零，现由第 8 节的连续种植床替代。新区域仍可用唯一 `id`、来源 `source`、置信度 `confidence`（`measured`、`photo_estimate` 或 `illustrative`）和本地米制多边形表示。灌木参数包括固定随机种子、数量、半径、间距和高度。

`tree_points` 可填写独立树点，每项包含唯一 `id`、`center_xz_m`、来源、置信度、`asset: existing_broadleaf`、可选 `scale` 与 `clearance_m`。点的来源要能支撑相应的置信度；当前样板没有可确认的单株树点，所以列表为空。有效树点会写入独立实例文件并复用现有宽叶树的绘制机制；不合格的点列入报告，不会静默放置。

在**已有地形、道路、门岗和树木资源已更新**的隔离副本中，可单独生成和检查植物，而不重跑全校园：

```powershell
python refresh_planting.py
python verify_planting.py
```

结果是独立的 `campus-annotated-shrubs.mesh`、`campus-annotated-trees.bin` 和 `campus-planting-report.json`。报告记录实际生成的灌木、通过或拒绝的树点及原因。生成器避开现有车道、人行网格、已映射建筑、水体、球场、桥及立德门岗；树点还避开校门范围和既有树点。检查脚本在实际样板上核查位置与来源，并使用独立虚构夹具测试树点接收、碰撞拒绝、重复生成和空图层。

这些避让不等于对所有场景物体的完整碰撞检测：未映射建筑、灯杆、架空结构和其他独立景点仍需针对新地点补充避让轮廓。植被照片只用于观察，不随资源打包；无实测点时不能把程序生成的位置称为真实树位。

## 7. 局部道路候选与安全比较

`data/road-surface-overrides.json` 是可审查的局部车行面候选配置，默认全部关闭，关闭时道路几何应与旧版完全一致。随附的立德门候选只从 OSM `way/220071403` 单独生成，避免把步行道误合并为车行道；其 GeoJSON 来自 OSM2World 0.4.0 输出并经坐标转换，地图数据须保留 ODbL 署名。照片可确认道路与草坪的相对关系，不能确定候选道路宽度，因此它目前是**示意，不是已验证的改进**。

候选显式启用后，生成器在建立道路标线、人行道、路缘、植被前统一应用候选面：限制在指定线段和局部范围、保留两端旧路并按中心线平滑过渡，限制旧路边缘最大内缩，并检查路口、其他道路、地图人行线或过街点、已映射障碍、中心线连续和增删面积。候选路径须位于 `data` 内并与来源 way 一致；这些检查不能发现所有未建模障碍或证明现实宽度正确。

要比较候选，请先备份并在隔离副本中把目标 `enabled` 改为 `true`，执行 `python generate_campus.py`、`python verify_road_overrides.py`、`python verify_lide_walk.py`、`python verify_planting.py`，再编译并用同视角及步行方式检查。全场景生成会重写资源；经审查、实景核对后才决定是否启用或同步。当前项目保留关闭状态。

还应在生成候选后将完整基线资源与候选资源做范围审计：`python audit_road_asset_scope.py --baseline-assets <基线assets目录> --candidate-assets <候选assets目录> --fail-on-nonlocal`。当前生成器对整体道路边界统一采样，局部变更可能重划分远处的路缘或铺装三角形；三角形记录变化不一定意味着可见表面变化，但在查明并解决之前不能把启用候选视作完成的局部更新。

当前样板的严格范围审计**尚未通过**：局部范围外的道路面、路缘及人行道均出现三角形记录变化。应先解决或证实这些非局部变化，再重跑范围审计、固定视角和步行检查；同时还需实测或可靠近景资料核对道路宽度。仅满足几何约束并不表示可以把候选用于正式场景。

进一步可用 `python audit_road_surface_geometry.py --baseline-assets <基线assets目录> --candidate-assets <候选assets目录> --output <结果.json>` 检查局部范围外的二维投影覆盖，并双向抽样比较高度、法线和 UV，同时检测切割边界上的覆盖差异。脚本不验证材质绑定、竖直面或抽样以外的位置，存在重叠投影时会跳过抽样；应结合严格记录审计和画面核查，不能据此证明模型完全相同。

对当前样板，完整重生成的远处道路面和人行道投影差异接近浮点误差；路缘投影在局部范围外分别有约 164.78 平方米旧覆盖和 164.88 平方米新覆盖不重合，说明整体边界重采样确实改变了路缘几何。隔离实验中，保留范围外原网格并切割拼接可将远处投影差异显著缩小，但路缘在切割边界仍有覆盖不一致，不能直接投入正式场景。下一步须让路缘以基线端点接合或局部重建，验证接缝、竖直面和纹理，再考虑启用。

## 8. 立德门至时光广场样板

`data/lide-corridor.json` 保存来源、航拍控制点和草坪角点。照片支持门岗红砖与浅色缘石、长草坪两侧的浅色铺装和低绿篱。门岗花坛的石边细节和树形、各段铺装宽度为视觉估计。保留原车行面及交叉口，长草坪南边按现有道路占地向内调整。航拍控制点的残差只衡量这四对点的拟合程度。

`generate_campus.py` 在自动层之后生成样板的铺装、草坪和花坛地面，并局部裁去冲突的自动人行道、草带与装饰。可以用已有地形和道路的资产副本单独生成；`<隔离目录>` 必须先存在或可创建。Blender 4.5 LTS 的脚本读取地形三角面贴地，生成有倒角和开放端的路缘、花坛收边及植被。将验证后的局部网格同步到 `assets`，保留原有其他资源。

```powershell
python campus_lide_corridor.py --assets assets --output <隔离目录>
blender --background --factory-startup --python-exit-code 1 --python blender_lide_corridor.py -- <隔离目录>/campus-lide-corridor-layout.json assets <隔离目录>
```

Blender 步骤写出两个运行网格及独立的 `lide-timesquare.blend`。工程文件用于修改和查阅，运行目录只需要网格与原有贴图。分步生成时把 `roadside-environment.json` 同步到 `data`，以便校验保留的灯位。若更改地形或样板平面轮廓，须再次运行 Blender 步骤并同步路缘和绿篱。用 `verify_lide_corridor.py --assets <完整资产目录> --baseline <原始完整资产目录>` 检查步道与广场衔接、净宽、避让和非局部资源。相机参数在 `assets/campus-lide-corridor-views.tsv`。可执行文件支持 `--corridor=gate`、`lawn`、`top`、`plaza` 四个机位。
